== what was wrong (reproduced with the owner's real data dir copy)
Startup restored a stored jar that only held Cloudflare cookies + view_adult:
  stored session for rPlakama@proton.me (session-incomplete)
The account name survived, so the header said "Hi, ..." while every write
surface said "Sign in to AO3 on the Session page to comment." — a signed-in
account was reported as signed out. Root cause of the lost jar: the adult-content
toggle persisted the current (wiped) jar unconditionally, overwriting the last
complete session with a useless one; the stored row then failed restore forever.

== fixes
1. src/server/session/mod.rs::persist_session refuses to store a jar without the
   AO3 session cookie (data-loss guard for every caller).
2. session_adult refuses and explains when the jar is incomplete instead of
   persisting it; the old good session can no longer be clobbered.
3. Startup clears an unauthenticatable stored session (logged:
   "cannot authenticate ...; cleared, re-import required") instead of restoring
   it on every start; the account name is kept for this run so the UI explains.
4. render/work WriteGate: Ready / WritesDisabled / SessionUnusable / SignedOut.
   Reader action bars and the comment area now distinguish them:
   - writes disabled -> "Writes are disabled on this AO3Instance ... AO3I_WRITE_ENABLED=true"
   - unusable session -> "Re-import AO3 session" + a re-import notice, never "Sign in"
   - signed out -> the existing sign-in prompt.
5. Page-wide banner on any page for session-incomplete/logged-out remembered
   sessions, and /session now shows the write switch plus the re-import warning.
