== feature
Reader (write gate ready): every cached comment shows Reply; the account's own
comments show Edit (only while they have no replies, AO3's rule) and Delete.
GET /write/comment/reply|edit|delete   editors / destructive confirmation
POST /write/comment/reply/preview      local validation + confirmation
POST /write/comment/edit/preview       local validation + confirmation

Reply:   exactly one POST /comments/<parent_id>/comments with comment[pseud_id]
         + comment[comment_content]; success 302 with #comment_<id> (audit
         "replied"); refusal text typed; shares AO3's comment rate limit
         (governor "comment"); cache thread refetched once, reader returns with
         the comment_posted notice.
Edit:    exactly one PATCH /comments/<id> with comment[comment_content] (audit
         "comment-updated"); own comments only; replies to the comment make the
         edit impossible (HTTP 400 before any request, mirroring AO3); AO3 may
         still refuse frozen/hidden comments; governor comment_edit 10/h.
Delete:  confirmation explains AO3's deleted-marker behaviour for commented-
         with-replies; exactly one DELETE /comments/<id> (audit
         "comment-deleted"); own comments only; governor comment_delete 10/h.
         AO3's permission failure is also a 302 (flash only), so the audit
         records the verified request rather than a guaranteed deletion.
After success the affected comment scope is refetched best-effort so the reader
shows the change; failures keep the cached thread. Links carry the cache scope
in the read context (work vs chapter), and the store gained find_comment.
