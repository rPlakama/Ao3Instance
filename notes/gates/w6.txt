== what the new integration tests prove
1. comment_is_discovered_confirmed_posted_and_audited
   - the reader shows a comment form for a signed-in session
   - POST /write/comment/preview discovers the default pseud from
     GET /users/someone/pseuds (fixture built from app/views/pseuds/*), then renders
     a confirmation page with the exact comment text and pseud name
   - POST /write/comment sends exactly ONE POST /works/12345/comments with
     comment[pseud_id]=111, comment[comment_content]=Hello world, CSRF token;
     the 302 Location /works/12345#comment_777 is parsed as success (comment id 777)
   - the pseud is persisted with the encrypted session; audit outcome "commented"
2. duplicate_comment_is_typed_and_audited_once
   - 200 re-render containing "already left this comment" -> typed failure, exactly one
     attempt, audit evidence carries the AO3 message
3. spam_and_rate_limits_have_their_own_notices
   - "looks like spam" -> spam-filter notice; HTTP 429 -> "3 per 15 minutes" notice
4. overlong_or_unconfirmed_comments_never_reach_ao3
   - >10000 chars rejected before any network; missing confirm=yes -> 400; the mock
     upstream saw no comment request
