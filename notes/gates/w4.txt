== what the new integration tests prove
1. subscribe_is_confirmed_audited_and_ledgered_then_unsubscribed
   - reader shows "Subscribe to work" for a signed-in session
   - /write/preview is a deliberate confirmation page
   - POST /write/subscribe sends exactly ONE request with
     subscription[subscribable_id]=12345, subscribable_type=Work and the CSRF token
   - ledger stores active subscription_id=42; audit logs outcome "subscribed"
   - duplicate subscribe is refused from the ledger with NO second upstream request
   - unsubscribe sends DELETE /users/someone/subscriptions/42.json using the stored id,
     marks the ledger removed, audit logs "unsubscribed"; /audit renders the trail
2. validation_failure_is_audited_and_not_retried
   - 422 from AO3 surfaces "AO3 rejected the action", the intent is marked failed,
     the audit row exists, and there is exactly one POST attempt
3. writes_require_the_switch_and_an_explicit_confirmation
   - with AO3I_WRITE_ENABLED unset every write route is 403 and no subscription
     request is sent (test asserts on captured upstream requests)

== safety spine
- one write at a time (governor holds its gate across the spacing sleep)
- per-action budgets (comment 3/900s, kudos 10/min, subscriptions 20/h)
- Retry-After parking
- intent row committed BEFORE the request; audit row after; no payloads/secrets stored
- confirmation required (confirm=yes), kill switch default off
